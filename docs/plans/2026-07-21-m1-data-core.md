# Milestone 1 — Data Core: Implementation Plan

Executes Milestone 1 of `docs/plan.md`. Builds on merged M0 (scaffold, constitution docs,
`@channelwatch/schemas`). Branch: `m1-data-core`.

## Global Constraints

- TypeScript-only; pnpm + Turborepo conventions from M0. New packages scoped `@channelwatch/*`, extend root `tsconfig.base.json`, Vitest, wired into turbo build/test/lint/typecheck.
- **Single source of truth:** taxonomies, confidence bands, `PUBLICATION_THRESHOLD`, and copy come from `@channelwatch/schemas` — never re-declared. If a needed constant is missing there, add it there (with tests), don't fork it.
- All numeric rules match docs/SPEC.md: evidence weights (§14.1), confidence formula (§14.2, worked example = 0.884), thresholds (§14.3), PE-label sourcing rule (§14.3), PE-backed conditions (§13.2).
- Classification is computed from active relationships, never stored as unexplained truth (docs/plan.md mod #5). `channels.published_classification` is a denormalized cache with explanation codes.
- Precision over recall; UNKNOWN/UNCLEAR are first-class outcomes. Tier 4 evidence never supports a published claim.
- Git: plain commit messages, no trailers. TDD for scoring and graph packages (RED evidence required).

## Task 2: `packages/scoring` (TDD)

`@channelwatch/scoring` — pure functions implementing SPEC §14. No I/O, no DB.

- `src/weights.ts` — `EVIDENCE_WEIGHTS`: the §14.1 table verbatim as a typed record keyed by a `SourceType` enum you add to `@channelwatch/schemas` (values: OFFICIAL_REGULATORY_FILING 1.00, OFFICIAL_ACQUISITION_ANNOUNCEMENT 0.95, INVESTOR_PORTFOLIO_LISTING 0.90, DIRECT_CREATOR_CONFIRMATION 0.90, CORPORATE_REGISTRY_RECORD 0.90, REPUTABLE_BUSINESS_PUBLICATION 0.80, ESTABLISHED_INDUSTRY_PUBLICATION 0.75, NAMED_EXECUTIVE_INTERVIEW 0.75, ARCHIVED_CORPORATE_PAGE 0.65, TRADEMARK_TRANSFER 0.65, SHARED_LEGAL_DOCUMENTATION 0.60, TECHNICAL_INFRASTRUCTURE_LINKAGE 0.35, ANONYMOUS_TIP 0.10, BEHAVIORAL_CONTENT_CHANGE 0.05). - `src/publication.ts` — `isPublishable(confidence)` (≥ PUBLICATION_THRESHOLD from schemas); `canPublishPeLabel(sources)` implementing §14.3's rule: at least one Tier 1 source, OR ≥2 Tier 2 sources from independent publishers (different `publisher` values) — takes `{tier, publisher}[]`. - `src/explanations.ts` — `explainConfidence(factors, sourceType)` returning human-readable strings built ONLY from neutral templates (no free-text interpolation of claims).
- Re-export `confidenceLabelFromScore` from schemas (do not reimplement).

## Task 3: `packages/graph` (TDD)

`@channelwatch/graph` — pure ownership-graph functions. Input: plain objects (channel id, `Relationship[]`, `Entity[]` per schemas types). No I/O.

- `src/graph.ts` — build adjacency from relationships; a relationship is ACTIVE iff `status === "ACTIVE"` (add nothing to schemas — compare against relationship status values already used by the data model docs; if a RelationshipStatus enum is missing in schemas, add it there: ACTIVE, ENDED, DISPUTED, PENDING_REVIEW) and `effective_to` is null/in the future relative to an explicit `asOf: Date` parameter.
- `src/direct-owner.ts` — direct owner of a channel = entity with an active OWNS / ACQUIRED / CONTROLS edge to the channel (precedence OWNS > ACQUIRED > CONTROLS; if multiple owners tie, return highest-confidence edge; ties → UNKNOWN with explanation code `MULTIPLE_OWNER_CANDIDATES`).
- `src/ultimate-parent.ts` — from the direct owner, follow entity→entity upward edges SUBSIDIARY_OF, PORTFOLIO_COMPANY_OF, and controlling OWNS/PARTIALLY_OWNS (control_level CONTROLLING) until no active parent. Cycle-safe (visited set; on cycle return chain-so-far + code `OWNERSHIP_CYCLE_DETECTED`). Returns the full chain, not just the top.
- `src/classification.ts` — `deriveClassification({channelId, relationships, entities, asOf})` → `{classification, directOwner, ultimateParent, chain, confidence, explanationCodes, warnings}`. Rules, in precedence order:
  1. Any load-bearing edge (owner chain) with status DISPUTED → `DISPUTED` (code `OWNERSHIP_RELATIONSHIP_DISPUTED`).
  2. PE in chain — direct/ultimate owner is `PRIVATE_EQUITY_FIRM`, or any chain edge is `PORTFOLIO_COMPANY_OF` whose parent is PE or PE-sponsored (§13.2) → `PE_BACKED` (codes `DIRECT_OWNER_CONFIRMED`, `OWNER_IS_PE_PORTFOLIO_COMPANY`).
  3. Owner is COMPANY / MEDIA_NETWORK / SUBSIDIARY / BRAND (no PE in chain) → `CORPORATE_OWNED`.
  4. Owner is CREATOR or PERSON, with an active minority FUNDS / INVESTED_IN edge into the channel or owner → `EXTERNALLY_FUNDED`.
  5. Owner is CREATOR/PERSON, or a company that is FOUNDED_BY the creator and the creator PARTIALLY_OWNS it with control_level CONTROLLING → `CREATOR_OWNED`.
  6. No active ownership edges but channel is researched → `OWNERSHIP_UNCLEAR` (code `NO_OWNERSHIP_EVIDENCE`).
     Classification confidence = min(confidence of load-bearing edges in the chain).
     Warnings (not classifications): `OWNERSHIP_CHANGED_RECENTLY` if any owner-chain edge `effective_from` is within 12 months of `asOf` (§9.4); `RECORD_OUTDATED` if a provided `lastReviewedAt` is older than 12 months.
     Note: `INDEPENDENT` and `OWNERSHIP_CHANGED` classification labels exist in schemas for API/UI use but this derivation never emits them in M1 — document that in code where the precedence list lives.
- Explanation codes: add an `ExplanationCode` enum to `@channelwatch/schemas` covering all codes used here (+ the two from SPEC §26.2).

Tests first (RED), including the acceptance case from docs/plan.md: the SPEC §35/§15.4 example graph (Channel X ← OWNS ← Production Company ← SUBSIDIARY_OF ← Media Group ← PORTFOLIO_COMPANY_OF ← PE Firm) derives `PE_BACKED` with the §26.2 explanation codes and correct ultimate parent. Also: creator-owned direct; creator LLC (FOUNDED_BY + PARTIALLY_OWNS controlling); minority-investment → EXTERNALLY_FUNDED; expired ownership (`effective_to` past) ignored; disputed edge → DISPUTED; cycle detection; no-edges → OWNERSHIP_UNCLEAR; recent-change warning at the 12-month boundary; min-confidence propagation.

Verification: package tests green; root green. Commit.

## Task 5: Research record format + importer

The seed-phase research workflow: one YAML file per channel in `data/research/`.

- Add `ResearchRecord` Zod schema to `@channelwatch/schemas` (new `src/research.ts`): `channel {youtube_channel_id (strict UC regex), display_name, handle?}`, `entities[] {slug, canonical_name, entity_type, legal_name?, jurisdiction?, website?, aliases[]?}`, `relationships[] {subject (slug|"channel"), type, object (slug|"channel"), ownership_percentage?, control_level?, effective_from?, effective_to?, confidence (0-1), status}`, `sources[] {ref, url, title, publisher?, published_at?, source_type (SourceType), tier (must agree with SourceType→tier map from scoring — validate), archive_url?, excerpt (≤500 chars), supports[] (relationship indices or claim descriptors)}`, `claims[]? {predicate, subject, object, effective_date?, confidence_factors {sourceQuality…} }`, `review {researched_by, reviewed_by?, notes?, last_reviewed_at}`. Cross-field refinements: every relationship must be supported by ≥1 source ref; PE-implying relationships (PORTFOLIO_COMPANY_OF, or owner entity_type PRIVATE_EQUITY_FIRM) must satisfy `canPublishPeLabel` over their supporting sources — importing fails otherwise with a clear message.
- `services/api/scripts/import-research.ts` — read `data/research/*.yaml` (use `yaml` package), validate via ResearchRecord, resolve entity slugs, upsert channels/entities/aliases/sources/relationships/claims idempotently (natural keys: youtube_channel_id, entity slug→canonical_name, source url), compute claim confidence via `@channelwatch/scoring` when confidence_factors given, derive classification via `@channelwatch/graph`, write `channels.published_classification` + `classification_confidence` + `last_reviewed_at`, and write one `audit_events` row per imported/changed record (action IMPORT_RESEARCH_RECORD, before/after state). Wire root `import:research`.
